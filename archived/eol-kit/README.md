# Datapack archive EOL — experimental, do not deploy

This is an offline prototype, not a release or a security boundary. The generator never modifies its source input. This draft also applies candidate output to the archived pack paths: see `INSTALLED-WIP.md` for known failing checks and `installed-packs.json` for locations. Original bytes remain in Git history and recovery backups. It does not retire mods. The migration manifest identifies copied upstream files and commits; copies do not remove upstream repositories or stop existing installations. No generated pack has been verified on a Minecraft server.

The intended lifecycle is relative to observed server ticks: 0–5,183,999 warning; 5,184,000–12,095,999 restricted functions; at 12,096,000 lock and best-effort scheduled function cleanup. Those are 72/168 hours only at 20 TPS; lower TPS, downtime, pause-when-empty and disabled tick tags extend wall-clock time. Versions get separate scoreboard identifiers using the supplied versioned pack ID; reuse of an ID shares state. Lifecycle state lives in world scoreboard and storage; resetting it or a privileged operator bypasses this mechanism. Removing the objective without its storage marker is not self-healing. An initial objective collision may log an error; repeated reloads should not re-add the objective when the marker persists. Notices are sent on first load and phase changes, not every reload; players who were offline can miss notices.

The restriction only covers executable .mcfunction files. Minecraft 1.20.2+ candidates have an early-return entry guard; earlier candidates gate every individual command because return is unavailable. Neither form has been validated against every Minecraft version or command behavior. Non-function features (advancements, loot tables, recipes, predicates, dialog actions), command blocks, operators, other datapacks, external APIs and scoreboard edits are not restricted. This is not world-wide read-only, not an access-control system, and not a defense against hostile packs. A function is allowed during phase 2 only if every non-comment command matches the very narrow read-only allowlist; mixed read/write functions are blocked in their entirety. Lifecycle scores, storage and tellraw remain writable. Guard wrapping may change execution semantics, notably macros, returns, execution context and function results; do not use until version-specific server tests prove compatibility.

Cleanup records completion but does not clear schedules or erase persistent data. Detected literal internal schedule targets are listed only for manual ownership review; detection is incomplete (including dynamic macro targets). Namespaced identifiers may be shared across packs. Unknown ownership must not trigger deletion.

Backslash line continuation is preserved unmodified in modern candidates; unsupported continuation in legacy packs is rejected. Both singular and plural function layouts receive lifecycle files and tags; unsupported overlays are rejected. Outputs are staged and published only after validation; failures remove the stage. UTF-8 is explicit and only newline characters split commands. Source hashes and paths are compared before publication, although concurrent modification after that comparison cannot be ruled out: run on an immutable snapshot.

The candidate archive contains 27 unvalidated version/source copies (including historical vorta-core variants). Guard coverage has been checked statically for 8,900 source functions, not at runtime. These are diagnostics, not deployable packs. Historical differences are preserved under archived/historical, while embedded mod resources are intentionally excluded from retirement. Complete per-version entry-point/resource review, real-server integration tests and safe upstream migration remain necessary before rollout.

Vanilla datapacks cannot execute shell commands or arbitrarily access operating-system files on their own. Commands may damage world data or socially engineer players; installed mods/plugins that expose command bridges, or software vulnerabilities, can change the threat model.

The owner explicitly prohibited Minecraft server tests or any bot/client joining servers. Do not start or join such servers. Offline static inventory and lifecycle model tests do not substitute for real game behavior. JSON advancement rewards and UI actions may create effects outside this system; consult `../eol-candidates/resource-audit.json`. The tick-based phases advance only while the world actually ticks. Candidate versions share original pack namespaces and are not designed to be enabled together; the unique lifecycle identifier alone does not prevent resource overrides.

For an offline reproducibility check, supply three independent source checkouts (`core`, `vortex`, and `vorta-core`) under a common directory, then run `python3 archived/eol-kit/rebuild_candidates.py --source-root /path/to/checkouts --output /path/outside/checkouts`. The tool requires every source byte and filename to match the manifest embedded in the existing candidate; it fails transactionally on mismatches. A local rebuild reproduced all 27 ZIP SHA-256 hashes. Reproduction is not a runtime validation.
