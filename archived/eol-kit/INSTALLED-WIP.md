# In-tree EOL installation — WIP, do not deploy

This draft applies the experimental candidates directly to 18 archived datapack locations, including both migrated Vortex source copies and the historical import copies. `installed-packs.json` maps each location to its candidate ZIP. Executable functions have an early return guard on supported modern versions or per-command gates on older versions; load/tick functions contain the 5,184,000 and 12,096,000 tick phase thresholds. The lifecycle is tick-based, not wall-clock time. Duplicate copies must not be enabled together.

This is **not a validated release**. No Minecraft server, client or bot was used. Command wrapping can change semantics; the mechanism only guards functions, not other game resources or commands, and is not a security boundary. Cleanup marks completion only; it does not clear schedules or remove persistent data because ownership is not proven. Existing installations are not automatically updated. Original source remains in Git history and the Vortex recovery bundle; independent backup packages are retained privately.

The in-tree copies have targeted post-generation fixes, recorded in `installed-packs.json`: comment-only provenance files retain their original bytes, legacy warning tests recognize their exact guarded command, InteractionClickDetection has a guarded warning wired after lifecycle initialization, and two packs no longer receive a second, incompatible function-tag layout solely because of comment-only watermark paths. The complete Python test suite and archive/warning/watermark checks pass offline. These fixes have **not** been incorporated into the candidate generator; rebuilding candidates alone does not reproduce these in-tree post-processing steps. `test_eol_installed.py` verifies the recorded differences and checks guard coverage.

`installed-packs.json` and the consolidation manifest record the checked-in modifications; imported original hashes remain recorded. ZIP candidate generation expects clean original source trees, not the guarded in-tree copies. The prototype still needs version-specific review and the limitations above remain before it can be considered a finished deployment.
