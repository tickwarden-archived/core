# Location in vortaforge/core

This directory contains the macroengine-modules project, including its own standalone Gradle build and Fabric-module generator. It remains separate from the root Gradle scan, so the move does not silently change existing `mods/` projects or their build.

The archived standalone pack is EOL-guarded and must not be used as mod input. The mod build instead uses a pinned, unretired copy from core commit `c6846148d7a60add52945e402e8092e8e5fea3da`, tree `4d34dd17548601b6a0d9f0a9001ead1f5e20d00f`, path `archived/packs/macroEngine-Datapack-v26.3`. A full Git history is required. From the core checkout, create an empty temporary directory and run `git archive c6846148d7a60add52945e402e8092e8e5fea3da archived/packs/macroEngine-Datapack-v26.3 | tar -xf - -C /absolute/path/to/empty-source --strip-components=3`. Copy this component to a separate writable work directory, run `python3 tools/split.py --source /absolute/path/to/empty-source --out . --in-place`, then `./gradlew check dist` with Java 25. The splitter refuses EOL-contaminated inputs; CI also scans generated resources and JARs for EOL markers. The generated `packs/` directory is an intermediate of the Fabric-mod build, not a published standalone datapack. Fabric jars still contain data resources.

The root `macroengine-modules.yml` runs the build in a runner temporary directory without starting a Minecraft server or connecting a game client. The nested upstream `.github/workflows/` files are preserved as historical references; they are not GitHub Actions workflows in this location. Publication is not automatic. Recovery bundle and original refs are in `recovery/`.
